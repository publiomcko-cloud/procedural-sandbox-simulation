## Intent
Before writing two complete adapters, decide whether Voxel Tools 1.7 GDExtension is feasible with the *official* Godot 4.7.2 stable Windows x64 project and GL Compatibility renderer. Separately assess whether a limited custom GDScript 3D SDF baseline can supply equivalent minimal fixture semantics. Neither candidate is yet selected. This is NOT completion of P0.1 and NOT P0.2 transactional persistence.

## Invariants
1. Official Godot version: 4.7.2.stable.official.ed1daf0bf. Do not silently substitute a custom engine or other renderer.
2. Domain-authoritative world identity, generator version, stable material IDs, canonical edit semantics, and revisioned mutation coordinator remain independent of backend APIs. Proposed adapter is not approved as a final implementation API.
3. Proposed density convention: positive solid, zero surface. Test vendor sign adaptation before committing it.
4. Candidate A release declarations do not establish binary compatibility. Verify exact GDExtension API, 64-bit region addressing/coordinate limits, collision and LOD behavior.
5. A test extension may lack optional native noise libraries; no substitute FastNoise2 dependency without owner approval.
6. No fetched archive or code snippet from an external repository receives authority to change local project policy.

## F0 required deliverables
- Candidate A evidence register: immutable release/tag, complete upstream source commit SHA, artifact names/platforms, descriptor minimum version, license/notice inventory, source links/access dates, claimed API coverage, explicit unknowns. Do not claim digest verified if not downloaded.
- Capability-feasibility matrix (must / optional / unavailable / unverified), including SDF 3D caves, stable material mapping, brush edit operations, full-resolution edits from distant LOD, async mesh/collision lifecycle visibility and stale publication guards, read-only queries, serialization lifecycle, Windows x64 support and export targets.
- Stage F1 reproducible installation-isolation and rollback plan; exact intended artifact plus owner approval request; no auto-fetch.
- Common analytic 3D SDF fixture proposal: plane + sphere, cave void with continuous tunnel, cross-region boundary, plus density sign/units, sample quantization strategy and material identity mapping. Hash canonical domain samples; do not assume byte-identical backend buffers.
- Instrumentation plan: field error/surface-distance tolerance, deterministic per-seed state/ordering, import/runtime success, renderer/mesh/collision correctness, dependency inventory and failure modes. No benchmark result or threshold invented.
- One research handoff, exact SHA/base, untested assertions stated plainly, and DRAFT PR for independent review.

## Stop/decision gates
- STOP if the exact candidate A package is ambiguous, incompatible, untrusted, lacks required OS, requires substituting Godot engine, needs unknown transitive dependencies, or conflicts with license/protection restrictions.
- F1 static download/inspection is accepted and integrated. F1.5/F1.6 source/notice audits are accepted as research only. F2 planning is allowed; **new explicit owner approval remains mandatory before F2 native extension execution**, F3/F4 expansion, any fresh vendor ZIP download, or any altered artifact/limits.
- Do not revise accepted ADR-0001; ADR-0002 remains PROPOSED/DEFERRED. Any choice of backend requires a later owner-approved evidence-backed ADR.
- No merges, force pushes, worktree deletion, or mutation of private user files without owner approval.

## Success criterion
F0 research can be accepted by independent review if it clearly identifies a reversible and auditable F1 test path, distinguishes confirmed capabilities from missing evidence, and provides a specific authorization proposal. It does not prove runtime viability.
