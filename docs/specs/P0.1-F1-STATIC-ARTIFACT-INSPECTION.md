## Authorized steps (F1 ONLY)
1. On Windows x64, create a separate feature worktree and an isolated GUID-unique TEMP child. Record clean Git status and path containment; do not write extension files to the Godot project.
2. Implement and TEST a PowerShell 7 / .NET ZipArchive preflight/extractor. Use locally GENERATED positive and malicious ZIP fixtures before downloading the real archive. Do not use Expand-Archive or tar as a substitute for path/type validation.
3. Download only https://github.com/Zylann/godot_voxel/releases/download/v1.7x/GodotVoxelExtension.zip (upstream commit 75d3c6d996ed2331c80edcd8c3ebc947afc0f041; release v1.7x). Expect exact size 54,457,774 bytes and GitHub metadata SHA-256 600737572a5e25541ba6f503e842a3717ba19afafa5474510a6ceff995a1d2d8. Independently compute SHA-256 from bytes before parsing/extraction. A match to GitHub metadata is integrity comparison, not independent authenticity attestation.
4. Read-only preflight EVERY archive entry before extraction; reject absolute, drive/UNC, traversal, colon/ADS, backslash, empty/reserved/path components, links/reparse and special files, non-NFC normalization issues, duplicate/case-colliding paths, prefix file/directory conflicts, mismatched attributes, and destination escapes. Reject excess resource use BEFORE extraction.
5. Only if complete preflight passes, manually stream regular files into verified unique empty TEMP root with CreateNew and actual-byte limits. Never restore unsafe metadata or invoke any archive-provided code, DLL, installer or Godot. Abort on truncated stream, compressed/decompressed mismatch, path escape, or any unexpected entry. Do not extract partially if preflight fails.
6. Produce static manifest for ALL files: normalized path, type, length, cryptographic file hash, extension descriptor mappings (including Windows x64 debug/release), native library names, licenses/notices, likely transitive components (SQLite 3.51.0, LZ4, meshoptimizer, FastNoiseLite, FastNoise2). Source inclusion is not proof of archive/binary inclusion. Classify unresolved provenance as UNKNOWN; stop before F2 proposal if any critical uncertainty.
7. Preserve exact commands, OS/PowerShell/.NET versions, synthetic safety test results, host permissions, URL, GitHub release metadata, computed hash, extraction limits, platform/notice findings, stop events, Git status, and rollback/cleanup evidence. Commit inspection source/test code and source-control-safe text/JSON manifests; do NOT commit native binaries, downloaded ZIP, or vendor source trees.
8. Cleanup only the exact canonical recorded GUID-root after validating it is a direct child of TEMP, outside any repository, and contains no links or reparse points. Never delete on unchecked failure, never use wildcard cleanup.

## Enforced F0 limits
Archive <= 100 MiB; <= 20,000 entries; single extracted file <= 512 MiB; declared and actual aggregate expanded bytes <= 2 GiB; max ratio 200:1; at least 2.5 GiB free disk; stream buffer <= 1 MiB. If legitimate archive needs changed limits, STOP for separate owner/evaluator authorization. Archive path checks and full zero-write preflight must be enforced, not merely described.

## Required tests before vendor ZIP processing
Synthetic positive archive; malicious path traversal/absolute paths/Windows reserved paths; symlink/reparse/special file flags; duplicate paths and Windows case/Unicode collisions; prefix conflicts; size/count/ratio overrun; declared-vs-actual size/truncated streams; confinement, preexisting targets and cleanup guard. Every failing fixture must prove no extracted payload. Log all assertions/exits. Do not claim tests passed without execution.

## HARD STOP conditions
Hash or length mismatch; any failed safety check; archive contents exceed caps; license/notice ambiguity; unsafe TEMP/repository boundary; missing Windows binary mapping; runtime or export requires custom Godot engine or further unapproved package; test failure. Preserve evidence, report BLOCKED or NEEDS_DESIGN_DECISION, do not bypass.

## Not authorized
F2 Godot/DLL loading or extension runtime validation; native builds; dependency installation into game; full terrain prototype, backend selection, approval of ADR-0002, F3/F4/P0.2, automatic merges. F2 requires explicit new owner authorization following F1 independent review.
