## 4. Ordered capability probes for future G1 owner-approved runtime

**Probe A — Import and identity:** Godot 4.7.2 official, GL Compatibility, Windows x64; verify extension descriptor resolves actual DLLs, GDExtension classes instantiate and clean Godot startup/shutdown with no unresolved imports. Record API errors. This is the FIRST actual native load; STOP on failure.

**Probe B — Minimal 3D field:** Deterministic non-FastNoise2 analytic SDF fixtures: planar surface + sphere, fully enclosed cave void and continuous tunnel/overhang, and multi-region boundary. Seed/version fixed; do not confuse vendor signed-distance convention with domain-proposed **positive solid**. Determine measured vendor sample sign, floating units, clamping/quantization, unloaded/pending states. Compare **canonical domain samples/field hashes**, not expected raw vendor buffer bytes.

**Probe C — Mesh and material:** Verify smooth Transvoxel mesh creation, visible cave/tunnel interior, coherent normals/winding, a stable material-ID-to-vendor-local mapping including missing-ID and more-than-four-blend capability limits. Use GL Compatibility-safe renderer/shader path; no unapproved compute/Vulkan requirement or substitute noise plugin.

**Probe D — Edits and first-LOD limitation:** Bounded subtract/add/sculpt/material updates including a stroke across at least two region boundaries. Record source revision, before/after sample values and mesh visibility. Test an edit beyond first-LOD loaded/editable coverage as an expected rejection or deferred-load limitation; NEVER silently claim arbitrary distant LOD edit support.

**Probe E — Collision/lifecycle:** Confirm collision shape generation and after-edit recook visibility, differentiate visual vs physics completion. Send two rapid edits; initiate an edit while mesh/collision build is pending; unload/reload or reset backend while work is in flight. Record whether public vendor API actually exposes completion/cancellation and prepublication revision fencing for mesh and collision. If old generation can publish over newer state and cannot be safely fenced by a wrapper, classify **unsupported/project-contract blocker**, not PASS based merely on eventual convergence. Do not modify upstream vendor C++ code to make a test pass.

**Probe F — Order, bounds, lifecycle:** Reorder region requests with the same seed/manifest; compare semantic sample hashes; test chunk-local coordinates translated from signed wide `i64_xyz` keys without representing domain identity as vendor `Vector3i`. Record supported range and fail explicitly on unsupported precision. Clean stop, optional save-modified-blocks/wait, reload/reopen checks limited to normal shutdown and rebuildable-cache semantics; canonical durable journal or crash recovery is **P0.2** and not demonstrated by a vendor save call.

**Probe G — Headless vs owner visual:** Execute bounded headless correctness checks only after Probe A and G1 approval; owner then runs an approved isolated GUI scene for surface/cave rendering, cross-region seams, LOD transition, and collision alignment. Owner records screenshot, steps, Godot build and result. Headless success is not equivalent to visual PASS. Export builds or extra platforms require separate listed approval if not included in the specific G1 scope.

## 5. Predeclared evidence and test standards

- Record exact SHA/paths for Godot executable, ZIP, two Windows DLLs (using accepted F1 manifest when comparable), checked-in scripts/fixture source, and session ID. No vendor bytes in PR.
- Each probe has deterministic input seeds, expected observation, outcome PASS/FAIL/UNSUPPORTED/INCONCLUSIVE, timestamps, log origin, exit code, timeout/safety state, API capability evidence, and a rollback checkpoint.
- Failure cases: missing/invalid DLL, incorrect Godot version or renderer, wrong density sign, unloaded-region queries, material ID overflow, cross-region stroke, early unload, dual edits and asynchronous mesh/collider publish lag. Design fixtures so the failed expected behavior cannot be mistaken for a successful unsupported capability.
- Do not invent time/memory performance thresholds or benchmark values. F2 is functional feasibility only. F4 contains separately scoped matched performance benchmark after owner-approved thresholds and hardware.
- Any requirement not observable from vendor public API must be reported as UNKNOWN or UNSUPPORTED; do not assert a race-free domain revision bridge without evidence.
- Security/compatibility hard stops: wrong ZIP/hash, wrong engine build, failure in archive safeguards, unsafe path/execution environment, network/subprocess surprise, unapproved dependency, unresolved native imports, crash before baseline test, unsatisfied GL Compatibility renderer, or inability to show consistent revision/collision semantics in allowed probe scope. Preserve logs and stop.
