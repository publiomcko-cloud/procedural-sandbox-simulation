## Purpose and decision

On the known Windows 11 Pro host (10.0.22631), `WindowsSandbox.exe`, Hyper-V VM cmdlets, VirtualBox and VMware control tools were not discoverable; Windows optional-feature status query required elevated privileges. A running hypervisor and `vmcompute` do not prove there is an isolated Windows guest.

**Preferred first diagnostic:** Windows Sandbox optional-feature status and availability, read from a separately **owner-opened Administrator PowerShell**. This is an authorized owner-side host administration task, **not a Codex/agent privilege escalation**. No command in this documentation should automatically elevate, enable features, reboot, download vendor bytes, or run native code.

**Alternative:** a dedicated, throwaway Windows VM with no connected virtual network adapter, a **standard nonadministrator** guest account, and no host shares or credentials. Favor this alternative if Sandbox guest account privileges cannot be constrained, resource/time supervision cannot be enforced, or the renderer cannot work under approved isolation.

## Owner-only host diagnosis (non-native)

Open Windows Terminal/PowerShell **Run as administrator**, then inspect:

```powershell
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber
Get-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM |
  Select-Object FeatureName, State
Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All |
  Select-Object FeatureName, State
Get-Command WindowsSandbox.exe, Get-VM -ErrorAction SilentlyContinue |
  Select-Object Name, Source
```

If `Containers-DisposableClientVM` is `Disabled` and Windows Sandbox is the chosen route, **owner only** may enable it deliberately:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM -All
```

Accept any OS-requested restart **only after saving other work**. Re-check feature state and Windows Sandbox presence afterwards. If enabling fails, the machine is already virtualized without nested-virtualization support, or a reboot is not possible, stop and document the blocker; do not install unapproved hypervisors or disable security features.

Reference: Microsoft [Install Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-install).

## Sample secure Sandbox configuration (PREVIEW ONLY)

Use `tests/f2_runtime/provisioning/F2-Isolated-Sandbox.wsb.example` as a **template**, not evidence of sandbox availability. It references the *owner-created*, narrowly scoped `C:\F2-Approved-Inputs` host directory; do not use any home/profile/worktree/secrets root as a mapped directory. The host folder must exist before launching. Copy/rename the example to a local `.wsb` file only after checking the path, OS support and safety settings.

Configured defaults deliberately include:
- `<Networking>Disable</Networking>`: **mandatory** because Windows Sandbox defaults to networking enabled.
- `<VGpu>Disable</VGpu>`: software WARP rendering; GL Compatibility must actually work with this choice, and performance is not being benchmarked. An inability to start the renderer is a **BLOCKED/INCONCLUSIVE** result, not permission to enable a riskier GPU path or run on host.
- `<MappedFolders>...` with only the preapproved inputs mapped **read-only**. Do not mount the code worktree, private directories or host-wide drives.
- `<ClipboardRedirection>Disable</ClipboardRedirection>`, no camera/microphone/printer, `<ProtectedClient>Enable</ProtectedClient>` if supported, and a finite memory allocation. **These settings are not substitutes for verifying effective protections**.
- No `LogonCommand`: launching Sandbox should not execute untrusted software automatically.

Windows Sandbox launches by default under **WDAGUtilityAccount**, typically administrator-capable. The **G1 unprivileged execution gate is NOT satisfied by opening the Sandbox window**. Prior to any vendor-code load, demonstrate that Godot will actually run using a standard/nonadministrator guest token (`whoami /all` in the exact launch context; validate Administrators group not enabled) and that process limits/supervision exist. If you cannot establish a standard user and safe process launch in Windows Sandbox, stop and choose a managed throwaway VM. Do not relax issue #26's restrictions.

Reference: Microsoft [Windows Sandbox .wsb configuration](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file) and [sample secure mapped-folder configuration](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-sample-configuration).

## Guest readiness checks — no vendor code

A guest may be marked `READY_FOR_STAGING` only if the operator records **observed evidence** of:
1. Disposable/isolated Windows guest identity, exact VM/Sandbox configuration, owner-controlled lifecycle and snapshot/discard.
2. Effective guest network disabled (not only a configuration-file assertion), no network interfaces attached where applicable, and no guest-side fetching.
3. Godot/native runtime will execute as **standard/unprivileged guest user**; no Administrator token, no credentials or private host shares present.
4. The mapping exposes only the intended verified **read-only** host folder; no guest write-back to host; clipboard/printer/audio/video redirection restrictions checked.
5. Owner-approved actual resource caps (memory, disk) and supervisor-enforced per-probe/overall time ceilings (5-minute/probe and 30-minute session proposal from issue #26). Windows Sandbox `MemoryInMB` is a memory allocation setting, not a proof of CPU/disk/time enforcement.
6. Safe evidence capture and export path, sanitized logs, shutdown/rollback/cleanup, and method to retain failure traces without restoring guest access to host.
7. GL Compatibility feasibility with the exact official Godot build is **not yet established**; recording a guest-ready state authorizes artifact preflight within the already approved G1 scope, not a claim that Probe A passed.

If any item is missing, report `BLOCKED_ENVIRONMENT`, record which item and the observed command/output, and do not download, extract or run the native extension as a shortcut.
