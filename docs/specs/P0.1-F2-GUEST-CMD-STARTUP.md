# F2 Guest CMD wrapper — fail-visible, diagnostic-only startup (Issue #41)

**Status: READY_FOR_INDEPENDENT_SOURCE_AND_OWNER_HOST_VALIDATION.** This source branch is based on draft PR #32 at `b280633ebd1adb47f116bcc3efb74896a4bf39b4`. No actual guest execution with this source has been observed. ## Design and security boundaries

Previously the `.wsb` LogonCommand used a nested PowerShell `-NoExit -Command` expression with quoting and a source-mapped PowerShell script. This change uses a **plain startup command without nested quotes**:

```xml
<LogonCommand>
  <Command>cmd.exe /k C:\F2Input\F2-Guest-Diagnostic.cmd</Command>
</LogonCommand>
```

The host pre-stages exactly **three hash-pinned, reviewed diagnostic input files** in the narrow folder `C:\F2-Approved-Inputs`. That folder is mounted to `C:\F2Input` with `ReadOnly=true`, with no other mapped folders. The three files are `F2-Guest-Diagnostic.cmd`, `Start-F2SandboxDiagnostics.ps1` and `Get-F2SandboxReadiness.ps1`. No vendor archive, ZIP, DLL or Godot executable is added. The Windows Sandbox vGPU, networking, clipboard, audio/video and printer redirections remain DISABLED; ProtectedClient remains ENABLED. The owner scope dialog and guard against staging while any WindowsSandbox process is active remain in force.

The small ASCII `.cmd` wrapper is the **stage-zero observation point**. Before opening another shell it prints `F2 GUEST WRAPPER STARTED` and `F2 STAGE: CMD_ENTRY`. It checks for the mapped PowerShell bootstrap and the OS PowerShell executable, displaying `BLOCKED_ENVIRONMENT` on a missing prerequisite. It invokes only the reviewed `Start-F2SandboxDiagnostics.ps1` via guest PowerShell `-NoProfile -ExecutionPolicy Bypass -File`. It then prints the **PowerShell process exit code without claiming the guest is ready**; cmd.exe `/k` keeps the guest console visible after script return, rather than waiting a fixed number of seconds. No credential is in this CMD script or any `.wsb` file. If even the CMD banner is missing, do NOT infer the bootstrap ran: troubleshoot Windows Sandbox LogonCommand start and mapping.

The PowerShell bootstrap remains separate and unchanged. It may use initial guest administrator privileges **only** to create a guest-local randomized, password-protected standard account; it does not run the readiness diagnostic under that administrator as fallback. The existing guest child diagnostic verifies the actual identity, nonadministrator token, network observations and read-only mapping, and reports UNKNOWN for renderer, enforceable CPU/disk/session supervision, future Godot launch identity, controlled evidence export and discard. Password/credential contents are never intentionally printed or written; the only user-visible artifacts are console status, banner, stage, sanitized exception category and child exit code. The CMD wrapper is **not** a security boundary or native process watchdog.
