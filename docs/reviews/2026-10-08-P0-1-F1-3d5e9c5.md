## Required corrections

**F1-R1 (MEDIUM; mandatory security-test coverage):** The controlling F1 spec explicitly requires negative tests of compressed ZIP byte cap and minimum disk availability, as well as asserted extraction confinement/cleanup. In scripts/tests/test-inspect-zip.ps1 the suite overrides entry count, per-file expanded bytes, aggregate expanded bytes and ratio, but never tests MaxArchiveBytes. Nearly all preflight test calls pass SkipDiskSpaceCheck, with no separate negative test for MinFreeBytes. Implementation has both guards, but mandatory tests are missing. Add synthetic cap test reducing MaxArchiveBytes below fixture size; add disk-free gate test setting MinFreeBytes higher than observed free space and calling WITHOUT SkipDiskSpaceCheck; verify both reject before any extraction. Restore mutated limits in finally. Explicitly assert no extracted payload and check failure label/message so an unrelated exception cannot pass an adversarial case.

**F1-R2 (MEDIUM; negative-test integrity):** Expect-Reject accepts ANY exception as a successful rejection, including an unrelated setup/runtime bug in the preflight. For the critical hostile fixtures, require expected error category or message and assert the ZIP preflight actually reached its intended guard, rather than merely throwing. Make synthetic test gate fail closed if any required fixture cannot be created; ensure the junction/cleanup guard test reports actual tested status. Record test labels and failure details in F1 handoff. The current generic helper reports rejection on any exception and can falsely pass a broken validator.

**F1-R3 (LOW; evidence semantics and pinned verification):** write-artifact-manifest.ps1 hard-codes native_code_loaded=false; it cannot observe whether a native library was loaded. The script accepts an arbitrary ArchiveSha256 parameter and verifies against that parameter, but does not assert that it equals the separately recorded pinned GitHub release digest, despite printing the pinned digest into its output. Do not present hard-coded negative runtime statements as automated observations; label as developer-declared/not-tested, and enforce the exact expected artifact size and pinned digest or validate a separate SHA verification record before producing an F1 success manifest. This does not call the developer's observed ZIP bytes into question.
