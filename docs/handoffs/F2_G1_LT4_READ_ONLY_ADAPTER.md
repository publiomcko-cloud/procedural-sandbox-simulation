## Actual implementation, not an authorization

- `scripts/f2-acl/lt4/F2G1LT4.ReadOnlyAdapter.psm1` implements a **physical Windows observation provider** for the exact LT-1/R2 set of 23 historical object names (8 directories, 15 files) and five immediate-child inventories. It checks object type, all fixed directory parents for reparse points, readable owner/SDDL, file-size bounds, read-only FileStream, complete byte reads, before/after content length/timestamps/ACL stability, and exact expected child inventories. It does not write to or repair any observed object, and does not assert atomic NTFS snapshots or an unobserved ADS/hard-link property.
- The provider has a fixed label-to-path mapper for fixture and historical host modes. **Host mode is permanently disabled at source level** by `$script:ProtectedHostAccessEnabled=$false` and has no exported invocation. A token check that reuses LT-2 GetTokenInformation must also pass before a host path is resolved. There is no procedural approval flag, owner URL or command-line option that can enable this build. Enabling host mode requires a **separately approved, exact-SHA reviewed source change**, followed by a **new explicit owner execution authorization**.
- The existing **R2 historic core is invoked without changing R2 source** from the adapter's disposable fixture mode: its reviewed owner/DACL, manifests, package files, capture, mailbox, evidence and coordinator rules remain the normative semantic evaluator. The adapter passes physically obtained fixture bytes and ACL observations to R2 through its provider callbacks. Under a later separately authorized real host mapping, the provider would select R2's historical `Live` semantic criteria rather than the synthetic `Fixture` criteria, but the legacy **R2 `-Live` entrypoint remains disabled and unchanged**.
- LT-3's accepted hash-on-byte-array evaluator compares physical bytes against the original seven package SHA-256 pins and three immutable manifest/payload/integrity SHA-256 values. Synthetic fixture bytes are correctly classified as mismatches: no test data is substituted for historical expected hashes.
- `scripts/f2-acl/lt4/Invoke-F2G1LT4.ReadOnly.ps1` exposes only a no-arguments **blocked host-readiness** report or `-SyntheticFixtureRoot` for disposable GitHub-hosted Windows CI. Both exit nonzero, both make `ProtectedReads=0` clear, and neither can report a real historical V2 host PASS. The fixture function is the only exported physical observation path.
- `scripts/f2-acl/lt4/Test-F2G1LT4.ReadOnly.ps1` creates fresh synthetic fixture files solely inside GUID-scoped disposable hosted runner temporary trees and verifies real physical observation, original R2 evaluation, negative inventory controls, zero observer mutations and always-disabled host entry. The test setup writes **only its new fixture**, not the historical C: package. The disposable CI runner deletes its own temporary filesystem after the job.
- `.github/workflows/f2-g1-lt4-readonly-adapter-source.yml` runs Windows PowerShell 5.1 fixture checks on a GitHub-hosted Windows runner with repository `contents: read`, checkout credentials not persisted, and retains accepted LT-3, LT-2, LT-1 and R2 suites.

## Precise claims and gaps

The adapter is physically implemented and connected to R2 policy, but all passed observations are disposable Windows fixtures. The historical protected C: contents were **not read**; the user has not attested a machine or supplied an execution grant. No current V2/V3/ACL/release state is inferred, and the fixture cannot claim expected live file hashes or owner/DACL policy were satisfied on the host.

The R2 core retains its **stricter check on Administrators group membership**; on a filtered UAC token from an admin account it may reject even though the LT-2 physical token classification would allow it. This is a *conservative functional limitation*, not an elevation bypass. Before host execution, the owner may use a genuinely standard account or separately approve a minimal policy change supported by a targeted test; do not silently weaken the R2 rule.

The adapter's path-based Get-Item/Get-Acl/FileStream observations and before/after rechecks meet the approved **trusted, uncompromised owner-managed Windows host** model, not resistance to a malicious concurrent privileged writer. Named ADS and multiple hard-link absence remain `LINK_ADS_NOT_ATTESTED`; this does not imply that required historical object hashes or ACLs were observed. The R2 semantic evaluator remains the authority for required historical fields; independent source review should inspect any integration issue that could prevent the actual intended read-only result.
