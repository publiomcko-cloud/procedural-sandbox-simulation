## Feasibility conclusions

- Windows Sandbox is **not feasible for the mandatory hard-gated G1 run as currently configured**: its documented `.wsb` controls do not provide CPU, disk quota, or wall-clock session enforcement. `MemoryInMB`, free-space monitoring, and a read-only host mapping do not replace those controls. Job Objects can constrain an associated child tree but not all guest activity.
- A pre-provisioned offline throwaway VM is the preferred candidate if it can provide a queried-back CPU/memory cap, independent <=30-minute host watchdog, fixed-size OS and scratch VHDX, no network device or enhanced-session redirection, standard-user execution, and a read-only verified input. This route is not present or validated by this task; if it needs feature installation/admin action or any gate cannot be enforced, stay `BLOCKED_ENVIRONMENT`.
- The Issue #43/44 screenshot proves only the reported diagnostic child token, zero adapters/routes, read-only mapping, and adapter inventory for that run. It does not attest the future Godot process token, all possible egress, GL Compatibility, hard resource limits, evidence export/discard, or native runtime.
- Renderer feasibility is `UNKNOWN`; require actual `gl_compatibility` runtime method and OpenGL evidence from the exact official Godot build with vGPU disabled after all other safeguards pass. No forced Forward+/Vulkan fallback.
- Proposed numeric limits are initial design ceilings, not owner-approved or demonstrated runtime guarantees. The inert matrix must prove actual enforcement before any native stage.

- Job Objects cover associated processes; process creation methods that bypass normal job inheritance and guest OS activity need separate detection/control. Failure to prove containment is a blocker, not a reason to label monitoring as enforcement.
- Fixed-size VHDX caps virtual capacity, but suitability, guest volume layout, and disk-full handling are unverified.
- Godot GL Compatibility under a vGPU-disabled disposable VM/Sandbox is untested. A Remote Display Adapter inventory is not GL proof.
- No evidence export/disposal route has been owner-confirmed.
- The candidate ceilings require independent technical review and owner acceptance before implementation; they are not performance claims.
