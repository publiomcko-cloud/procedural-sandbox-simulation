## Implementation summary / rationale

Issue #31 says the owner enabled the optional feature and Sandbox opened earlier. In this developer session, `WindowsSandbox.exe` was found at `%WINDIR%\System32\WindowsSandbox.exe`, but the optional-feature query required elevation and no elevated query was attempted. The `.wsb` was statically inspected; it was not opened in a GUI. Thus this work does not convert owner-reported history into a fresh observation and does not claim guest readiness.

The host checker pins the reviewed guest script by SHA-256, rejects root/profile/worktree/reparse-point paths, accepts only the fixed mapping directory and one expected plain-text script, validates the required offline/read-only `.wsb` settings, reads feature state without attempting elevation, and does not overwrite unexpected content. The guest script records identity and `whoami /all`, admin membership, adapters/routes, mapping contents and write denial, OS/graphics inventory, visible memory/free disk, plus UNKNOWN for actual Godot token, GL Compatibility, enforced CPU/disk/time limits, and evidence export/discard.

No native extension, Godot executable, archive, installer, guest logon command, third-party dependency, or network/clipboard/vGPU relaxation was added. No security feature was changed. MemoryInMB is explicitly not treated as process or time supervision.
