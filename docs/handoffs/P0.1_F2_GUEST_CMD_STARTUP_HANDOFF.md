This establishes that the persistent CMD window corrected the former blank-console symptom. The screenshot reports **standard-user token PASS / Administrators False**, **network PASS (0 active adapters and 0 default routes)** and **read-only input mapping PASS**. CPU/disk/time supervision and evidence export/discard are UNKNOWN. **No native F2 A-G probes were run.**

The standard-user JSON itself reported `Diagnostic overall: INCOMPLETE`. The outer bootstrap incorrectly reported `BLOCKED_ENVIRONMENT / DiagnosticGateFailed` with the misleading message that a network or read-only gate had failed. Notably, `Standard-user child exit code` was absent, even though the outer CMD wrapper showed **PowerShell bootstrap exit 0**. In previous source, the gate included `$process.ExitCode -ne 0` without accounting for a null/unavailable child `ExitCode` from `Start-Process -Credential -PassThru`. This is classified as a **missing exit-code observation**, not proof that networking failed.

The new source-only correction adds **production** `Resolve-F2ChildDiagnosticResult`, tested against synthetic normal, unavailable/noninteger/nonzero exit, network/mapping FAIL and UNKNOWN, invalid token, malformed/missing child output, missing native-code attestation, and unexpected child overall states. A genuine child ExitCode 0 together with nonadministrator token and network/mapping PASS yields `INCOMPLETE`, **never READY_FOR_STAGING**. Missing ExitCode yields `BLOCKED_ENVIRONMENT / ChildExitCodeUnavailable` even when individual isolation checks report PASS. Real nonzero code yields `ChildProcessFailed`; actual network/mapping problems get their own error categories. The bootstrap attempts to retain its child process handle while the child is running, then refreshes its process object on completion. This is a hypothesis-driven mechanism to obtain a reliable ExitCode; guest behavior remains **unverified** until a new owner screenshot. Null is NEVER converted to 0, and the bootstrap now returns a nonzero process exit for blocked statuses so its outer CMD wrapper does not misleadingly show success.
