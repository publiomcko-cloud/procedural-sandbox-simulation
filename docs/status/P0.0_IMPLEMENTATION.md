# P0.0 implementation record — 2026-10-08

**State:** Visual failure correction committed for review; owner F5 retest and independent evaluator review are pending. This record does not mark P0.0 or Phase 0 complete.

## Scope delivered

- Added `RegionGenerator`, a pure-data pseudo-generation fixture using explicit world seed, algorithm version 1, and `Vector2i` region key. Its Park-Miller LCG stream is initialized separately for each region request, so output does not depend on request/traversal order. The 8x8 default and 64x64 maximum are test bounds, not terrain dimensions or a world-generation contract.
- Expanded the Godot `SceneTree` smoke suite to check deterministic output, region/request-order independence, seed/key variation, dimensions, bounded values, invalid inputs, stable failure codes, and diagnostic messages.
- Strengthened Windows and shell validation to check the pinned engine and return nonzero on environment/runtime failures, while still attempting independent runtime stages after an environment mismatch.
- Corrected the bootstrap camera pitch after reproducing the gray output. Added an instantiated-scene regression test for the main scene, current camera, camera target projection, reference mesh, Compatibility renderer, and directional light.
- Retained the existing local `project.godot` configuration and Godot-generated `.gd.uid` files.

## Architecture

The fixture produces nested arrays and metadata only. It does not create scene nodes, modify authoritative world state, or claim a terrain algorithm. No addon, plugin, network dependency, or external package was added. Algorithm changes require a new version rather than silently changing version 1 output.

## Visual failure diagnosis and correction

Owner's PR #4 report records a gray F5 window at failed SHA `9e85ef1a9e31022e1ba57e15bd054a941d455f21`. Reproduction on Godot 4.7.2 with the real Compatibility renderer used `--path game --resolution 800x600 --write-movie <temp>.png --quit-after 30 --fixed-fps 30`; it exited 0 and printed `SANDBOX_BOOTSTRAP_READY`, while every captured frame was uniformly gray.

Runtime inspection of the instantiated scene found the main scene loaded, bootstrap `_ready()` ran, the unit `BoxMesh` existed and was visible in-tree, and the camera and enabled directional light existed. The renderer was `gl_compatibility`. The camera's old forward vector was `(0, 0.5, -0.866025)`: it pointed upward. The origin projected to `(576, 904.3712)` in a `(1152, 648)` viewport, outside its bottom edge. This confirms the saved camera transform—not startup, mesh creation, lighting, or a runtime error—caused the blank gray view.

The scene now expresses the camera position and pitch directly: position `(0, 4, 9)`, rotation `(-24, 0, 0)`. Its forward vector points downward, and the origin projects to `(576, 323.7236)`. A new non-headless Godot capture on the Compatibility renderer shows the reference cube at the center: [P0.0 bootstrap render](P0.0-bootstrap-render.png). This captured game frame verifies actual rendered pixels on this machine, but does not replace the owner's F5 retest or acceptance.
